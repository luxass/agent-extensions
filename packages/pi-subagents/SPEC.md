# Pi subagents: behavior for approval

## S1. Start and name agents

I ask Pi to delegate work, or type `@explorer review authentication`. A type mention asks the main model to start that type and prepare its task. The model uses `Agent` to start agents or `resume` to continue finished agents. Each new agent requires a unique lowercase task name, with hyphens between words, such as `auth-review`. Names are never reused within the session. A rejected call does not use up its name. There are no numbered fallback names. Agents run in the background unless `run_in_background: false` asks Pi to wait. The model can read results with `get_subagent_result`, send corrections with `steer_subagent`, and stop work with `stop_subagent`. The `Agent` description lists available types and their tools. Task names cannot equal type names. A missing saved conversation or unavailable type produces an error, never a replacement agent.

## S2. Mention an agent type

I type `@explorer review authentication` to ask the main model to start an explorer. It always asks for a new agent, whether other explorers are running or finished. Autocomplete lists available types and says that submission asks Pi to start one. It does not list existing task names. Only a leading type mention with a message has this meaning. Bare mentions, unknown names, file attachments, and mentions inside sentences keep Pi's normal behavior. An explicit file path disambiguates a file from an agent type. Mentions never send directly to an existing agent or continue one. I give corrections and continuation requests to the main model in ordinary words.

## S3. Define agent types

I define agents in Markdown files. Later locations replace earlier definitions of the same name: built-ins, `~/.pi/agent/agents/`, `~/.agents/agents/`, `.agents/agents/`, then `.pi/agents/`. Project locations apply only when I trust the project. The seven allowed frontmatter fields are `name`, `description`, `tools`, `model`, `thinking`, `max_turns`, and `skills`. Only `description` is required. A name uses lowercase words joined by hyphens and defaults to the file name. An invalid file is skipped with one warning naming the file and offending fields, including unknown fields. The body follows Pi's base system prompt. Listed skills contribute their full text, while all other skills remain available. A model is `provider/id` or a fragment matching exactly one available model. File values for `model`, `thinking`, and `max_turns` win over the same call parameters. Without a model or thinking override, an agent inherits its caller's values.

## S4. Choose tools

I get two built-in types: `general-purpose` with `read, bash, edit, write`, and `explorer` for read-only work with `read, grep, find, ls, bash`. There is no planner. Omitting `tools` selects `read, bash, edit, write`. Built-in tool names enable those tools. Naming an extension tool loads its owning extension only in that agent. No unrelated extension loads, including this extension. Agents have no UI, so a tool that needs to ask me something fails with an error inside an agent. Naming `mcp__server__*` enables matching MCP tools and codemode, but connects every configured MCP server. Only the main session coordinates agents. Agents cannot start, steer, or stop other agents. `Agent` and `Agent(a, b)` are not supported in agent tool lists. Agents share the project's files. The explorer's read-only instructions are not a filesystem sandbox because it has `bash`.

## S5. Receive results

Background results appear automatically as compact, expandable chat blocks. While the main session keeps working, results enter at its next boundary without an extra turn. A result the main model has not read when it stops is delivered as an idle result. While idle, `delivery.mode: "grouped"` combines agents started during the same main request, not each model turn. It waits at most 60 seconds after the first result becomes ready, then reports completed work without waiting for stragglers. `"immediate"` reports ready results without waiting for siblings. Automatically delivered text longer than 8000 characters is cut and points to `get_subagent_result` for the full result. Results already returned to the model are not delivered again. An agent stopped by the model sends no automatic result. Agents I stop myself report without starting a main-model turn. Every other automatic idle result starts a main-model turn, including agents the main model starts after a type mention.

## S6. Steer, stop, and limit work

I ask the main model to send corrections to running agents. I can stop running or queued agents in `/agents`. Stopping an agent affects only that agent. Pressing Esc in the main session stops the agents it is waiting for. Background agents keep running. Ctrl+B moves all running foreground agents into the background without stopping them. It acts only while such agents run, with no dialog open, and ignores key releases. After a few seconds, foreground rows show `(ctrl+b to run in background)`. One turn before `max_turns`, an agent receives a request to wrap up. At the limit, Pi stops it only if work remains and marks its result partial. Zero means unlimited turns.

## S7. Include context and reload

When the model sets `inherit_context`, the new agent receives the conversation the main model currently sees. This includes compaction summaries as user messages, but excludes tool calls without results. Agent conversations are saved under `~/.pi/agent/subagents/<main session id>/`. After `/reload`, or after I quit Pi and resume the session, finished agents remain listed, readable, and continuable. Agents that were running or queued show as interrupted and can be continued. An agent interrupted before it started has no earlier conversation, so continuing it starts one with the new prompt. Their interrupted runs never deliver a late result. A forked or cloned session starts without agents.

## S8. Watch and open agents

A live widget above my editor lists running agents with activity, turns, tool uses, tokens, and context percentage. I can show background agents only, all running agents, or no widget. An `Agent` call in the chat is a card. While the agent runs, the card shows its type, task name, and current activity. When it finishes, the card shows status, turns, tool uses, tokens, elapsed time, and one line of the answer, and I can expand it to the full answer. The widget, the cards, and `/agents` use the same status marks. Text from agents is cleaned before display, so control sequences in their output cannot change my terminal.

`/agents` opens two panes. The left lists every running, queued, and finished agent. The right shows the selected agent's full conversation with Pi's normal tool-call rendering, collapsed by default. The header shows model, thinking level, and status. Tab switches panes. In the list, Up and Down select an agent, and Enter opens the reading view: the list hides and the conversation fills the panel. Esc returns from the reading view to two panes, and Esc in two panes closes the viewer. The list's `x` key stops the selected agent after a second press, and `f` switches fullscreen and floating in either view. The viewer has no message input or continuation command. Up, Down, Page Up, Page Down, Home, and End scroll the conversation. If I scroll up, the view stops following and a `↓ N new messages` marker shows unread additions. End follows new output again. In fullscreen, I can use the mouse wheel and scrollbar, click an agent to select it, and click a tool call to expand or collapse it. Every mouse action also has a key. With the conversation focused, `t` and `T` move a cursor to the next and previous tool call, and Enter expands or collapses the call under it.

## S9. Configure and observe

I configure `subagents` in Pi's own `settings.json`, not a separate file. Pi merges global and trusted project values field by field. Defaults are `maxConcurrent: 8`, `maxTurns: 0`, `backgroundByDefault: true`, `disabledAgents: []`, `widget: "background"`, and `delivery.mode: "grouped"`. Excess background agents queue. Types named in `disabledAgents` cannot be started or continued. `maxTurns` applies when neither the agent file nor the call sets a limit. Invalid fields each produce one warning and use their defaults. Other extensions can observe `subagents:ready`, `subagents:created`, `subagents:started`, `subagents:activity`, `subagents:steered`, `subagents:usage`, `subagents:completed`, `subagents:failed`, and `subagents:disposed`. Their payload types are available through `@luxass/pi-subagents/api`. Other extensions cannot start, steer, or stop agents through these events.

## S10. Scope

I install `@luxass/pi-subagents` as a normal Pi extension. It does not provide direct human messaging to agents, nested agents, worktrees, persistent agent memory, scripted workflows, scheduling, package-shipped agents, cost displays, colored name badges, or editors for settings and agent files.
